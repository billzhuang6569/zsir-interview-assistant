# 01 · 产品设计

## 1. 一句话

让线上采访的嘉宾在自己电脑上，用一个几乎不用配置的小程序，录出**摄像头+话筒**、**桌面+系统声音**两条独立高清视频；导演远程遥控、远程检查、远程取回。

## 2. 用户与场景

| 角色 | 是谁 | 技术水平 | 他关心什么 |
|---|---|---|---|
| **嘉宾** | 被采访者，一次性用户 | 不能假设任何技术能力 | 装起来别麻烦、别影响我开会、别偷录我、用完能删干净 |
| **导演** | 庄Sir团队，重复用户 | 熟悉拍摄流程，不写代码 | 现场绝不能翻车、随时确认画面对不对、素材稳稳拿到手 |
| **后期** | 剪辑师 | 熟悉达芬奇/Pr | 两条文件清晰、分轨、能对齐、格式能直接导入 |

典型流程（一次采访）：

```
采访前一天              采访前 15 分钟                    采访中                 采访结束
导演创建房间，填好    →   嘉宾从固定地址装客户端、     →  导演倒计时开录、   →  停录 → 宫格图检查
信息，拿到 6 位邀请码      完成引导，最后输入邀请码进房     每 5s 看静帧           → 自动上传 → 结束任务
把「下载地址 + 邀请码」      看到欢迎信息，收起等待
发给嘉宾
```

## 3. 产品原则

1. **本地优先**：录制不依赖网络。断网、服务器宕机、导演关页面，录制照常进行，文件照常写盘。网络只负责遥控和监视。
2. **零惊吓**：嘉宾端不弹窗、不抢焦点、不出声；开始录制前一定有 3 秒倒计时；录制中一定有明显红点；没录时摄像头/话筒/屏幕捕获进程不运行。
3. **宁可少功能也不出错**：每个功能都有明确的失败兜底；现场用不到的功能一律不做。
4. **用完即走**：「结束任务」一键卸载干净，只留录制文件。

## 4. 客户端（嘉宾端）

### 4.1 形态

- 常驻**角落小浮窗**，默认右上角，可拖到任意角落；尺寸约 280×96 pt；始终置顶。
- 不在 Dock / 任务栏显示主窗口，只有一个托盘（菜单栏）图标。
- **不会被录进自己的屏幕录制**，也不会出现在会议软件的屏幕共享里（技术保障见 02 文档 §5）。
- 支持 macOS 13+（Intel 与 Apple Silicon）、Windows 10 1903+ / Windows 11。

### 4.2 首次启动流程

| 步 | 画面 | 行为 |
|---|---|---|
| 1 | 欢迎页 | 一句话说明 + 隐私承诺（见 06 文档） |
| 2 | 权限引导 | macOS：屏幕录制、摄像头、麦克风三项，逐项带截图指引，实时显示已授权/未授权；Windows：摄像头与麦克风隐私开关检测 |
| 3 | 设备选择 | 摄像头（默认第一个外接，否则内置）、话筒、显示器（多屏时必选），每项有实时预览/音量条 |
| 4 | 自检 | 3 秒试录 → 显示两路静帧、音量、文件可写、磁盘剩余、编码器类型；全绿才能进入下一步。**整个自检不需要联网、不需要邀请码**，嘉宾可以提前一天自己装好、自己检查 |
| 5 | 输入邀请码 | 6 个大格子输入导演给的 6 位数字码；输入满 6 位自动校验。成功 → 显示房间欢迎卡；失败 → 行内提示「邀请码不对或已过期，请和导演确认」 |
| 6 | 欢迎 & 就绪 | 欢迎卡显示：房间名、导演名、导演写的欢迎语、嘉宾姓名（若房间只填了一位嘉宾则自动带出，多位时让嘉宾选自己的名字，没填则让嘉宾输入）。点「准备好了」→ 收起为角落小浮窗，浮窗显示「已连接导演」 |

自检失败项要给出嘉宾能看懂的处理建议（例如「摄像头被其他软件占用，请先关闭 Zoom 的摄像头或改选其他摄像头」）。

为什么邀请码放在最后、而不是放在前面：

- 装程序、给权限、选设备、自检这四步都只和嘉宾自己的电脑有关，导演还没建房间嘉宾也能先做完；真正需要和导演「碰头」的只有最后一步。
- 邀请码一输对就立刻看到「导演 + 欢迎语」，嘉宾马上知道自己进对了地方、接下来等谁，是整个引导的终点而不是中间的一道关卡。
- 邀请码之后不再有任何可能失败的步骤，不会出现「码对了但自检没过、不知道该找谁」的尴尬。

客户端记住已加入的房间（7 天内再次打开直接回到浮窗，不用重新输码）；浮窗「⚙ 设置」里可以「退出房间」换码。

### 4.3 角落小浮窗

```
┌──────────────────────────────────────────┐
│ ● 就绪   张三   已连接导演          ⚙  ─  │
│ 📷 1080p ✓   🖥 2560×1440 ✓   🎤▂▅▃ 🔊▂▁  │
│ 剩余 312 GB                  [ 开始录制 ] │
└──────────────────────────────────────────┘
```

状态行颜色语义：灰=未连接导演（仍可本地录）、绿=就绪、红闪=录制中、黄=有警告、红=有错误。

录制中显示：时长、两路各自状态与实时文件大小、按剩余磁盘估算的可录时长；按钮变为「停止录制」（需长按 1 秒或二次确认，防误触）。

### 4.4 功能清单

| 功能 | 行为 | 失败兜底 |
|---|---|---|
| 本地开始/停止 | 嘉宾自己点，无需导演 | — |
| 远程开始/停止 | 收到导演指令，倒计时 3-2-1 在浮窗显示后开始 | 离线期间收到的「开始」不执行；「停止」在重连后执行 |
| 录制范围 | 两路 / 仅 cam / 仅 screen，导演可选，嘉宾可见 | — |
| 回传静帧 | 收到「检查」立刻抓两路当前帧；录制中每 5 秒自动抓 | 网络失败静默丢弃，不影响录制 |
| 宫格图 | 停止后对每路文件每 30 秒抽帧拼图，上传 | 生成失败则上传错误事件，本地仍保留文件 |
| 自动上传 | 停止后分片断点续传成品到对象存储，浮窗显示进度，可暂停 | 断网自动续传；网速过差时导演可切换为人工传 |
| 设置 | 设备、输出目录、画质档位（推荐/高/省空间）、浮窗位置 | — |
| 结束任务 | 嘉宾或导演触发；嘉宾确认后卸载程序并清理数据，**保留录制文件** | 成品未上传校验通过时导演端按钮禁用（嘉宾端可用但有强提示） |

### 4.5 输出

- 默认目录：macOS `~/Movies/庄Sir采访/`，Windows `%USERPROFILE%\Videos\庄Sir采访\`。
- 每次录制一个子目录：`<房间名>_<YYYYMMDD-HHMMSS>/`
  - `cam.mp4`、`screen.mp4`
  - `session.json`（开始时间、两路首帧偏移、分辨率、帧率、设备名、客户端版本）
  - `cam_sheet.jpg`、`screen_sheet.jpg`
  - `log.txt`
- 格式：H.264 High + AAC，fragmented MP4（崩溃可恢复），分辨率与码率见 02 文档 §4。

## 5. 控制端（导演端）

### 5.1 访问

- 固定网址，无登录（当前版本仅内部信任人员使用；后续若对外需加访问令牌，见 06 文档 §3）。
- 多人同时打开，所有人看到同一状态；每个操作记录触发者昵称（首次打开页面时填，存于浏览器）。

### 5.2 页面结构

```
顶栏：  庄Sir线上采访助手 · 控制端          [+ 新建房间]   我是：李导  ●已连接服务器
左栏：  房间列表（今天 / 最近 7 天）
主区：  当前房间
        ├ 房间信息：名称、邀请码（大字，一键复制）、[复制邀请文案]（下载地址 + 邀请码 + 三步说明，直接发微信）
        ├ 客户端卡片 × N（通常 1 个嘉宾）
        └ 事件日志（谁在几点做了什么、客户端告警）
```

### 5.3 客户端卡片

```
┌ 张三 · macOS 14.5 · 客户端 v0.3.1 · 已连接 32 分钟 ────────────────────────┐
│ ● 录制中 00:14:32        磁盘剩余 312 GB（约 9 小时）                          │
│                                                                              │
│  ┌──────────────┐  ┌──────────────┐                                          │
│  │  cam 静帧     │  │ screen 静帧   │   📷 1080p30 ✓ 11.2 Mbps  🎤 ▂▅▃        │
│  │  5 秒前       │  │  5 秒前       │   🖥 2560×1440 ✓ 9.8 Mbps  🔊 ▂▁        │
│  └──────────────┘  └──────────────┘                                          │
│                                                                              │
│  [ 检查 ]   [ ■ 停止录制 ]   范围 ◉ 两路 ○ 仅摄像头 ○ 仅屏幕                     │
│  [ 宫格图 ]  [ 文件 ]  [ 结束任务 ]                                            │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 5.4 按钮行为

| 按钮 | 行为 | 边界 |
|---|---|---|
| **检查** | 立即请求两路静帧，卡片更新并显示「x 秒前」 | 静帧超过 15 秒未更新：时间戳变黄；30 秒：变红并提示「客户端可能卡住」 |
| **开始录制** | 两端同步显示 3-2-1 倒计时；可先选范围 | 客户端未就绪（自检未通过/离线）时禁用并说明原因 |
| **停止录制** | 二次确认弹层（显示已录时长） | — |
| **宫格图** | 弹层展示两路宫格图，每格带时间码，点击放大 | 生成中显示进度；失败显示原因 |
| **文件** | 显示两路文件名、大小、时长、本地路径、上传进度、下载链接、SHA-256 校验状态 | 可一键复制「请从 xxx 目录手动拷贝」文案发给嘉宾 |
| **结束任务** | 二次确认 → 向嘉宾端发起 → 等嘉宾确认 → 显示结果 | 成品未全部校验通过时禁用，鼠标悬停说明 |

### 5.5 房间管理

新建房间弹层要填的信息：

| 字段 | 必填 | 说明 |
|---|---|---|
| 房间名 | 是 | 如「2026-10-28 王老师专访」，也是嘉宾端录制文件夹的名字 |
| 导演 | 是 | 默认带出本人昵称 |
| 嘉宾姓名 | 否 | 可填多位。填了一位：嘉宾端自动带出；多位：嘉宾端让嘉宾选；不填：嘉宾端让嘉宾自己输 |
| 欢迎语 | 否 | 显示在嘉宾端欢迎卡上，例如「王老师您好，今天采访约 1 小时，开始前导演会和您打招呼，录制时请保持这个小窗口不要关闭」 |
| 录制范围默认 | 否 | 两路 / 仅摄像头 / 仅屏幕，默认两路 |

点「创建」→ 服务器生成 6 位数字**邀请码**（全局唯一、7 天有效）→ 房间页顶部大字显示。

**客户端下载地址是固定的**（例如 `https://<host>/download`），和房间无关，嘉宾装的永远是同一个安装包。邀请码只在客户端引导的最后一步输入。「复制邀请文案」按钮生成一段可直接发给嘉宾的话：

```
您好，这是我们采访用的录制小程序：
1. 下载安装：https://<host>/download
2. 按提示允许权限、检查画面
3. 最后一步输入邀请码：482 913
装好后会显示「已连接导演」，就可以等我们开始了。
```

- 邀请码 7 天有效；过期房间只读，邀请码作废。
- 一个房间允许多个客户端（多嘉宾圆桌），卡片并排；同一个邀请码多台电脑都可以进。
- 房间可以「归档」，归档后邀请码立即失效。

## 6. 非功能要求

| 项 | 要求 |
|---|---|
| 稳定性 | 录制进程与 UI 进程分离；UI 崩溃不影响录制；任何一路异常 2 秒内两端可见 |
| 画质 | 摄像头按设备原生最高（上限 1080p30，可选 4K）；屏幕按原生分辨率（4K 可选降到 2560 宽），15/30 fps 可选 |
| 体积 | 推荐档：两路合计 ≤ 12 GB/小时 |
| 延迟 | 指令到执行 < 1 秒（正常网络）；静帧回传 < 3 秒 |
| 安装 | macOS 签名+公证的 .dmg；Windows 签名的 .exe 安装包；双端 < 60 MB |
| 兼容 | macOS 13+（Intel/Apple Silicon）、Windows 10 1903+ / 11；核显、N 卡、A 卡硬件编码，无硬编时自动降档软编 |
| 多显示器 | 支持选择任一显示器；HiDPI 缩放正确 |
| 语言 | 中文优先，英文备用（嘉宾端两种，控制端中文） |

## 7. 验收标准（P2 可对外版本）

1. 嘉宾从收到链接到「就绪」≤ 5 分钟，全程不需要导演语音指导。
2. 连续录制 2 小时，两路文件完整、音画同步误差 < 1 帧、两路起点对齐误差 < 2 帧。
3. 录制中强制杀掉 UI 进程、拔掉网线、让会议软件共享屏幕——录制不中断，文件完整。
4. 录制中强制断电（拔电源的台式机），文件最多丢最后 4 秒，可正常导入达芬奇。
5. 成品上传后 SHA-256 与本地一致；「结束任务」后嘉宾电脑上除输出目录外无残留。
6. 导演端 3 人同时打开，操作与状态一致，事件日志可追溯。
