# 07 · 路线图（M0–M5：先最小验证，再逐步扩展）

原则：**每一步都能在真机上跑给人看**，验收过了再扩展下一步。先证明「系统双路录制」这件最难、最核心的事在两个平台都成立，再往外包浮窗、联网、安装包。

| 里程碑 | 一句话 | 范围 | 验收（由 Claude 在真机执行，Billy 抽查） |
|---|---|---|---|
| **M0 · 骨架** | 仓库能构建 | 目录结构、`client-macos`（SwiftPM）/`client-windows`（.NET 8）/`server`/`control` 空工程；GitHub Actions 三条流水线；本文档与 08 协作流程 | CI 全绿；本机 `swift build`、Windows 机 `dotnet build` 通过 |
| **M1 · 最小验证：双路录制 CLI** | 不联网、无 UI，命令行录出两条文件 | `recorder capture --out <dir> [--tracks cam,screen] [--duration <s>]`、`recorder preflight --json`、`recorder devices --json`；屏幕+系统声 → `screen.mp4`，摄像头+话筒 → `cam.mp4`；fragmented MP4；硬件编码；`session.json`；Ctrl-C / SIGTERM 优雅收尾 | 两平台各录 10 分钟：文件能被 ffprobe 解析、时长正确、两路起点偏移 < 100 ms；`kill -9` 后文件仍可播放；CPU 占用（Mac M 系列 < 25%，Win 核显 < 40%）；Billy 导入达芬奇确认 |
| **M2 · 本地可用的浮窗客户端** | 嘉宾不联网也能自己录 | 角落浮窗（就绪/倒计时/录制中/警告）、引导 1–4 步（欢迎/权限/设备/自检）、本地开始/停止、输出目录、UI 与录制进程分离 + 看门狗、不被录进屏幕 | 浮窗不出现在自己的录屏与 Zoom/腾讯会议共享里；UI 进程被杀录制继续；自检失败提示可读 |
| **M3 · Relay + 控制端最小版** | 导演能在网页里建房间、遥控开停 | Relay：房间/邀请码、`/api/join`、WS hub、state/指令转发、事件日志、SQLite；控制端：房间列表、新建房间、邀请码、嘉宾卡片（状态/开始/停止/倒计时）、事件日志；部署到服务器 | 用 mock 客户端联调；两个浏览器同时开控制端状态一致；服务器重启后房间仍在 |
| **M4 · 客户端联网** | 嘉宾输码进房，导演远程开停、看静帧 | 引导 5–6 步（邀请码/欢迎卡）、WSS 客户端与重连、hello/state 心跳、远程 start/stop 与倒计时同步、「检查」静帧、录制中 5 s 静帧 | 一次真实内部采访：导演远程开录、看到静帧、远程停录，文件在嘉宾机上完整 |
| **M5 · 安装包与上线** | 第一版可运行版本上线，mac/win 安装包齐备 | `.dmg`（ad-hoc 签名 + 「右键打开」指引）、`.exe`（Inno Setup，未签名 + SmartScreen 指引）、`/download` 页、GitHub Release、服务器正式部署（Caddy + TLS，需域名）、README 使用说明 | Billy 用一台没装过的 Mac 与 Windows 机按下载页流程走通；控制端远程开停成功 |

**M5 完成 = 本轮目标达成。** 之后：M6 宫格图、M7 分片上传 + 文件面板、M8 结束任务与自卸载、M9 签名与公证、M10 多嘉宾/HEVC/对齐哔声。

## 执行顺序与并行

```
M0 ──► M1-mac ──► M2-mac ──┐
   └─► M1-win ──► M2-win ──┼─► M4-mac / M4-win ──► M5
   └─► M3 (server + control) ─┘
```

M1 两个平台可以并行，M3 与 M1/M2 无依赖也可并行；但**M1 没过真机验收之前不开 M2**（录制核心的接口要在真机上定型）。
