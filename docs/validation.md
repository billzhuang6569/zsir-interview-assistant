## 1. 分阶段交付

| 阶段 | 产物 | 退出门槛 | 阻断后续的失败 |
| --- | --- | --- | --- |
| P0 采集可行性 | 两平台最小双路原型、真实测试记录 | 会议共存、音频分离、小窗排除、2小时同步、异常素材恢复 | 任一核心平台不可用，先收缩支持矩阵而非包装发布 |
| P1 本地闭环 | 设备/权限/目录设置、试录、小窗、收尾恢复 | 断网独立使用；UI退出/崩溃不丢引擎状态 | 保存假成功、文件覆盖、素材不可恢复 |
| P2 远程闭环 | 会话授权、多人免登录导演页、命令/状态/静帧 | 幂等、失联、撤权、跨会话隔离验证通过 | 未授权查看/录制、旧命令重放 |
| P3 素材检查 | 落盘解码宫格、元数据、异常与重试 | 时间码准确、短片/长片分页、缺帧提示、原片不变 | 宫格掩盖损坏、误删原段 |
| P4 试用发行 | 签名安装包、支持清单、运行与故障文档 | 真实采访试录、剪辑导入、更新回滚及结束任务卸载验收 | 任意 P0 数据丢失或权限缺陷 |

暂停的范围决定在 P0 完成到 P1 协议冻结之间完成；若纳入，增加暂停/恢复/崩溃后时间映射测试。第2套界面已选定，按补充需求修订后可进行前端原型，但不能据此跳过采集门槛。

## 2. 支持矩阵记录方式

每行记录 OS 完整版本、CPU/GPU、内存、摄像头/驱动、话筒、输出设备、屏幕数量/缩放、磁盘类型、会议软件版本、应用版本、参数和结果。先覆盖 Apple Silicon、Windows x64 两条候选，再根据实际嘉宾设备决定 Intel Mac、Windows ARM 等，不宣称未测组合可用。

会议覆盖腾讯会议、飞书会议、Zoom；分别先会议后录制、先录制后会议。内置/USB 摄像头、内置/USB/蓝牙音频，多屏/不同缩放、输出设备变化均纳入。任何硬件支持承诺以已通过清单为准。

## 4. 测试记录与质量门槛

记录模板：用例ID、日期、执行者、版本/提交、完整环境、输入参数、操作步骤、期望/实际、测量数据、脱敏证据位置、结论与未决问题。成功/失败都保留，失败不得以换一台设备覆盖旧记录。

建议发布目标：每个声明支持的关键组合至少连续3次两小时录制；可靠性样本量仍有限，不宣传绝不崩溃。崩溃恢复测多次不同时间点，公开真实丢失上界和边界条件。出现素材覆盖、不可解释丢失、未授权访问或假成功，立即阻断发行。

预览检查不是成片检查；文件首尾检查不是全片检查；工具链编译成功不是实机验收。每项报告必须保留这个证据层级。
