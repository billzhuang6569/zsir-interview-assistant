## 1. 本轮决策

| 事项 | 建议 |
| --- | --- |
| 更新来源 | 默认 GitHub Release 的静态 updates.json；可配置用户服务器上的同格式 HTTPS 清单 |
| 更新动作 | 自动检测、提示、浏览器下载；不自动替换、提权、退出或重启应用 |
| 服务部署 | 不开发动态后端；Nginx、Caddy 或对象存储托管清单即可，安装包可选镜像 |
| 兼容下限 | macOS 13.0 Ventura，保留摄像头、系统声音、双路录制和多屏选择 |
| 更旧系统 | macOS12.3+独立兼容包（Intel/M），桌面无系统声音；12.0–12.2及11不支持 |
| 发布 | 六包同版本：Mac13+ Intel/M、Mac12.3+兼容版 Intel/M、Windows x64/ARM64 |
| 自动检测范围 | 本轮仅Mac13+完整版；Windows延期，Mac12兼容版手动下载 |

选择静态清单的原因：同一协议同时解决 GitHub 和自托管，不需要数据库、登录、API 密钥、定时爬取或额外常驻服务。比直接解析 GitHub Releases API 更容易加入每包最低系统要求，并避免客户端依赖公开 API 的共享 IP 配额。GitHub 官方支持 latest/download/固定文件名跳转，详见文末来源。

本轮不引入 Sparkle/WinSparkle，不做自动安装、增量更新、强制更新、预览渠道切换、遥测、服务端升级管理后台。用户要求的是版本检测，保留现有 ZIP 安装方式即可。

## 2. 规划起始时的实现基础（历史基线，兼容代码已更新）

- macOS：SwiftPM 的 `.v14`；`script/build_and_run.sh` 的 target triple、Info.plist 最低系统均为 14.0。
- `CaptureEngine.swift`、`SettingsPreview.swift` 直接调用 `SCContentFilter.contentRect/pointPixelScale`，本机 Apple SDK 标注 macOS 14.0。
- `SettingsPreview.swift` 使用的 `SCScreenshotManager.captureImage` 标注 macOS 14.0。
- `DeviceSelection.swift` 的 `.external`、`.microphone` 类型标注 macOS 14.0，降构建目标时必须兼容替换。
- ScreenCaptureKit 的音频输出、capturesAudio、sampleRate、channelCount、excludesCurrentProcessAudio 标注 macOS 13.0。选择 13 可沿用系统声音管线，不额外安装虚拟音频设备。
- 当前没有客户端版本检查。Windows 为 .NET 8 WinForms；两端均可使用系统 HTTP 客户端。当前安装包无正式发行签名，Mac 无 Apple 公证。

上述是规划起始时源码与 SDK 的确认结果，不等于已完成全部 API availability 审计或 macOS 13 真机验收。

## 3. 版本检测交互

在高级设置底部增加“版本与更新”，不占用主录制窗口：

- 当前版本、上次检查时间及结果。
- “检查更新”按钮；“自动检查更新”开关，默认开启。
- 默认来源 GitHub；折叠的来源设置中可选“自定义服务器”并填写 HTTPS 清单地址，支持恢复默认。切换前验证格式/读取成功，失败不覆盖工作中的配置。
- 自动检查在首次进入空闲后异步执行，成功/失败均记录尝试时间，常规最多每 24 小时一次。手动检查可绕过周期，防重复点击；限流必须遵守 Retry-After。
- 录制、收尾保存、恢复素材时不启动自动检查、不显示更新提醒；已发出的请求可完成，但提示延迟至空闲。更新请求不能更改录制状态。
- 新版提示显示版本、简短纯文本摘要、系统要求和“下载新版 / 稍后 / 忽略此版本”。自动提醒每个版本一次；手动检查仍能找到被忽略版本。“稍后”最早下次启动提醒。
- 下载动作在浏览器打开匹配平台/宿主架构的安装包 URL，提示停止保存并退出后再替换；应用不自行下载/执行文件。
- 离线/超时/格式错误：自动检查安静失败，设置页显示上次状态；手动检查显示原因和重试。禁止把失败写成“已是最新版”。

隐私说明：仅向配置的来源发起常规 HTTPS 请求，服务方会看到网络 IP 与通用 User-Agent；不发送素材、录制报告、设备ID、账户或录制内容。关闭自动检查后仅用户点击检查时联网。

## 4. 清单协议与选择规则

默认检测地址（计划新增资源，v0.2.0 尚不存在）：

`https://github.com/billzhuang6569/zsir-interview-assistant/releases/latest/download/updates.json`

清单格式 `schemaVersion: 1`，包含稳定版本记录列表。每条记录：

| 字段 | 约束 |
| --- | --- |
| version | 稳定 SemVer，如 0.3.0；比较数值段，禁止字符串字典序比较 |
| publishedAt | UTC ISO 8601；显示信息，不作为版本排序依据 |
| summary | 有限长度纯文本，不执行 HTML |
| releaseURL | HTTPS 发布说明页 |
| assets | 每包包含 os、arch、edition、minOS、url、size、sha256 |

`os` 为 macos/windows，`arch` 为 arm64/x86_64（Windows x64 文件名映射为 x86_64）。minOS 使用版本元组；Windows 保留最小系统 build 信息，如 x64 10.0.19041、ARM64 10.0.22000，不能把市场名称直接作版本比较。SHA-256 是64位十六进制，size为正整数。

选择步骤：校验协议 → 丢弃不稳定/撤回记录 → 先按产品edition（standard/monterey）匹配，再按系统和宿主架构筛选资源 → 筛选 minOS ≤ 当前系统 → 选择最大版本 → 与包内当前版本比较。Mac Rosetta / Windows x64 仿真进程不能被误认为宿主是 x64；本轮Mac需检测原生机器架构；Windows检测实现延期。开发测试可注入系统/架构，不伪造生产环境。

清单保留近期版本，并为各最低系统代际保留最后可用版本。未来最新版不支持当前系统时，仍可找到最后兼容更新；若当前已是最后兼容版本，显示“当前系统可用的最新版本；更高版本需要升级系统”。缺少匹配资产时不猜下载文件名、不推荐其他架构、不强制降级。服务端回滚不会令客户端降级。

网络策略：总超时10秒、清单大小上限256 KiB、有限重定向、全程HTTPS；拒绝URL用户信息和非HTTP协议；缓存按来源隔离，ETag/304复用已有成功结果，没有缓存的304重试完整请求。来源变化清除旧ETag与忽略状态。自定义源故障不静默切回GitHub，避免与用户选择不一致。

不在客户端内置 GitHub token 或服务器管理密钥。更新摘要不作为指令执行。哈希用于发布一致性；本期浏览器下载后客户端并不自动验包，不能宣传已完成安装安全验证。若后续实现自动安装，必须另做发行签名与安装/回滚设计。

## 5. 自托管方式

用户只需静态站点，无后端进程：

1. 用既有打包产物生成六包校验和和清单；先校验版本、架构、最低系统。
2. 将清单放到例如 `https://<用户域名>/zsir/updates.json`；示例域名不是已部署地址。
3. 仅镜像清单时，包URL仍指GitHub；若要下载也不依赖GitHub，则同步六包到版本目录，并改清单中资源URL，字节与SHA256必须相同。
4. TLS证书有效、提供正确Content-Type、ETag/Last-Modified，短缓存（建议5分钟）；客户端原生HTTP不需要CORS。
5. 始终先上传所有包、验证可下载，再原子替换清单。回滚恢复上一版清单，保留旧包，不改已有tag或同版本包字节。
6. 未来实施交付 Nginx/Caddy 中一种最简配置与部署/回滚说明；实际主机、域名、路径由部署时确认，本轮不操作服务器。

GitHub 同样先建 draft，上传六包、SHA256SUMS.txt、updates.json，验证完再公开并标 Latest。缺任一包或元数据不一致则阻止发布。

## 6. macOS 13 兼容设计

不建立单独“旧版客户端”，仅在必要 API 边界分支：

| 能力 | macOS 14+ | macOS 13 |
| --- | --- | --- |
| 录制像素尺寸 | 保留 filter.contentRect × pointPixelScale | 统一辅助函数结合显示模式像素/逻辑尺寸、方向，实测核对实际帧尺寸 |
| 屏幕缩略图 | SCScreenshotManager | 低分辨率、无音频、短生命周期 SCStream，获取首个完整帧后停止 |
| 设备枚举 | 当前外置设备/麦克风类型 | 使用系统可用旧类型，按ID去重，保持用户选择 |
| 录制/音频/封装 | 现有管线 | 同一管线，保留系统声音和恢复逻辑 |

13缩略图流必须：排除本应用窗口、串行逐屏采样、单屏超时（建议3秒）、错误/取消后停止并释放；不生成Take、不启动音频、不写磁盘，迟到回调不能恢复已关闭画面。不能为适配简单使用整桌面截图而丢失自窗口排除。

尺寸计算共享给缩略图、码率/容量、实际录制，避免三处口径不同。重点验证缩放显示、Retina、外接非Retina、竖屏、镜像；SCDisplay.width/height不是已证实的物理像素，不能直接代入编码尺寸。

实施时先将分支构建目标降至13.0获取全部编译错误，逐项审计 SwiftUI、AVFoundation、ScreenCaptureKit、权限状态与媒体恢复。改动涉及 Package.swift、build_and_run.sh、DeviceSelection、CaptureEngine、SettingsPreview，其他仅按审计需要修改。SDK版本可以较新，部署目标和产物最低系统必须确实为13，不是只修改Info.plist。

macOS12.3+已开发独立兼容测试包，桌面不含系统声音，摄像头保留麦克风。开发与验证见 [独立计划](macos12-compatibility-plan.md)。无旧机实测，正式发布必须披露限制。

## 8. 验收与发布门槛

- 版本用例：0.9.0→0.10.0、相同/更旧、预览版、非法版本、缺架构/资产、最新不兼容但旧版兼容、没有可兼容更新、宿主与进程架构不同。
- 网络用例：正常/304无缓存/离线/403/429/超时/截断JSON/未知schema/超大响应/不安全URL；失败不能影响录制。
- 更新交互：自动每天一次、关闭后不自动联网、稍后/忽略/手动重查、录制/保存/恢复中延迟提示、不同来源缓存隔离。
- macOS13 ARM64及Intel实机：首次权限/拒绝/返回检测，内置与USB设备、静音/有声桌面、摄像头+桌面，预览退出释放、自窗口排除、多屏目标一致、拔屏保存和恢复副本。
- macOS14+两架构回归；Windows x64/ARM64最终包开箱启动与真实录制（自动检测延期）。虚拟机可辅助，但不可代替物理设备采集验收。
- 媒体短录核对首尾与声音；至少30分钟冒烟记录同步、丢帧、资源；这不替代后续1小时以上采访可靠性验证。
- 六包同版、包内版本/架构/minOS核验、远端下载哈希一致、清单仅包含已公开可访问包，README及发布说明同步。
- 若旧系统测试未通过或无环境，不降低公开支持声明；修复/缩小发布范围需重新说明，不把“能编译”当“可用”。

## 9. 首次迁移与风险

v0.2.0没有更新检测入口，无法靠服务器“推送”使旧客户端突然获得该功能；用户需要手动升级到首个带检测的版本。此后才可自动检测后续版本。

GitHub网络可达性由用户网络决定；自托管清单不自动解决GitHub包下载问题。两端无正式发行签名的现状本期不自动改变，更新提示必须沿用现有安装说明。macOS权限深链接和系统要求重启的行为需在13实际验证。
