# 0.5.0 开发计划：Windows 界面对齐、Windows 摄像头、全平台「在录屏里隐身」

基线：`main` @ `e7199c0`（0.4.1）。本文件是计划，不代表已实现。实施按下文分 PR 进行，每步都要在 Windows 实机留证。

## 0. 反馈与结论

| 反馈 | 结论 | 性质 |
| --- | --- | --- |
| Windows UI 与 Mac 不一致、错位 | 布局用 96 DPI 像素写死，没有设置 `AutoScaleDimensions`，字体又按磅值随 DPI 放大；设置窗没有套暗色样式；屏幕卡片的图片和文字重叠 | 缺陷，已在代码中确认 |
| Windows 乱码 | 已确认的一项是屏幕卡片上文字压在缩略图上，加上显示的是系统内部名 `\\.\DISPLAY1`，用户看起来像乱码。另有两处编码隐患。其他位置要等用户提供截图才能定位 | 部分确认 |
| Windows 无法识别、无法录制摄像头 | Windows 客户端**没有实现**摄像头和话筒，配套 FFmpeg 也没有编译 DirectShow 输入 | 缺功能，不是设备兼容问题 |
| 远程协助时看不到录制助手 | Windows 主窗和边缘红圈都固定设成了 `WDA_EXCLUDEFROMCAPTURE`。远程协助软件本质上也是录屏，所以同样看不到。这个状态不能关闭 | 新功能：做成开关 |

## 1. 原因分析

### 1.1 UI 错位与 Mac 不一致

1. **DPI 缩放失效**（主因）。`MainForm` 设置了 `AutoScaleMode.Dpi`，但没有设置 `AutoScaleDimensions`，因此控件尺寸不会被缩放；而 `Font` 以磅为单位，会随 DPI 变大。以下尺寸都按 96 DPI 的像素写死（[MainForm.cs:59-72](../../clients/windows/MainForm.cs)）：
   - 窗口 `ClientSize = 352×380`
   - 说明文字 `MaximumSize = 320`
   - 标题栏图标、标题和按钮用 `Bounds` 绝对定位（标题宽 218，最小化和关闭按钮在 x=260/292，大小 28×28）
   - 主按钮 `MinimumSize = 124×36`

   截图中的屏幕是 3072×1920，系统缩放比例高，所以出现了：标题被图标压住、按钮被裁切（“开始录制”右边的灰块是被裁掉的“素材目录”和“刷新设备”，原因是 `WrapContents=false`，见 [MainForm.cs:90](../../clients/windows/MainForm.cs)）、文字意外折行。代码里没有处理 `DpiChanged`，所以窗口拖到另一块缩放比例不同的屏幕上还会再错位一次。
2. **设置窗没有样式**。全局只调用了一次 `StyleControls(layout)`（[MainForm.cs:96](../../clients/windows/MainForm.cs)），设置对话框没有调用，因此下拉框和按钮是系统默认的白色，灰字压在浅底上，系统标题栏也是浅色，与 Mac 的深色设置页明显不同。
3. **屏幕卡片重叠**。卡片固定为 270×170，图片宽 240、高按比例算；16:10 屏幕的图片高约 150，加上 `ImageAboveText` 的文字就超出了卡片，导致文字盖在图片上（[MainForm.cs:174-178](../../clients/windows/MainForm.cs)）。
4. **结构与 Mac 不同**。Mac 主窗依次是：状态点+阶段、说明、计时、机位分段选择、预览折叠、宽主按钮+文件夹图标+齿轮图标（[CaptureView.swift](../../clients/macos/Sources/ZSirCapture/CaptureView.swift)）。Windows 是一列纵向排下的大按钮（录制设置 / 实时预览 / 开始录制 / 素材目录 / 刷新设备 / 更改保存位置），没有机位选择。另外，“画面 / 系统声音”设备表格构建好了却没有加入布局（[MainForm.cs:79-82](../../clients/windows/MainForm.cs)），属于残留代码。

### 1.2 乱码

已确认：
- 屏幕卡片的文字与缩略图重叠，加上直接显示 `\\.\DISPLAY1` 这种系统内部名（见 1.1-3）。

隐患（必须在实现摄像头前修掉）：
- 调用 FFmpeg 时，`StartInfo` 没有指定 `StandardErrorEncoding / StandardOutputEncoding`（[Recorder.cs:606-610](../../clients/windows/Recorder.cs)）。FFmpeg 输出的是 UTF-8，含中文的路径和设备名有可能按系统代码页解码，导致 `capture.log` 和报错提示出现乱码。摄像头设备名要从 FFmpeg 输出中解析，例如“集成摄像头”，编码错了会直接匹配不到设备。
- 发行包把 `INSTALL.md` 复制成 `README.md`，文件是不带 BOM 的 UTF-8（[package-windows.ps1:55](../../script/package-windows.ps1)）。在旧版记事本或其他编辑器里可能按 ANSI 打开，显示成乱码。

需要用户补充：如果“乱码”指的是其他位置（标题、按钮、弹窗、文件名），请提供截图以及系统语言和缩放比例。

### 1.3 Windows 摄像头

- README 和开发文档都明确写着“不采集摄像头或话筒”，界面里也没有摄像头和话筒的选择（[clients/windows/README.md](../../clients/windows/README.md)）。
- `script/build-windows-tools.sh:58` 只启用了 `--enable-indev=gdigrab,lavfi`。没有 `dshow`，也没有 `mjpeg` 和 `rawvideo` 这类常见摄像头格式的解码器。所以即便在命令行里调用 FFmpeg，也无法打开摄像头。
- 录制报告里的 `mode` 写死为 `"desktop"`（[Recorder.cs:616](../../clients/windows/Recorder.cs)）。

### 1.4 远程协助看不到界面

- Windows：主窗在 `Shown` 时设置 `SetWindowDisplayAffinity(0x11)`；如果设置失败，会直接禁止录制（[MainForm.cs:137-138](../../clients/windows/MainForm.cs)）。边缘红圈也做了同样的设置，而且自动收起依赖这个设置成功（[RecordingEdge.cs:28](../../clients/windows/RecordingEdge.cs)）。ToDesk、向日葵、TeamViewer、QQ 远程等工具都通过 DXGI/GDI 截屏，因此一律看不到小窗。
- macOS：自己的录制通过 `SCContentFilter` 排除本应用（[CaptureEngine.swift:427-429](../../clients/macos/Sources/ZSirCapture/CaptureEngine.swift)），只有边缘红圈设置了 `sharingType = .none`（[RecordingEdgeController.swift:28](../../clients/macos/Sources/ZSirCapture/RecordingEdgeController.swift)），主窗口对远程软件是可见的。两个平台的行为不一致。

## 2. 方案

### 2.1 「在录屏里隐身」（全平台，默认开启 = 当前行为）

| | 开启（默认） | 关闭 |
| --- | --- | --- |
| Windows | 主窗、边缘红圈、设置窗都设为 `WDA_EXCLUDEFROMCAPTURE`。设置失败时禁止开始录制（保持现状） | 设为 `WDA_NONE`：远程协助和会议共享可以看到小窗。**小窗也会出现在本次桌面录制中**（Windows 没有按应用排除的采集接口）。开始录制前提示一次 |
| macOS | 主窗、设置窗、红圈都设为 `sharingType = .none`；自己的录制仍用 `SCContentFilter` 排除 | 设为 `.readOnly`：远程协助可以看到小窗；**自己的录制仍然排除小窗**（只有 Mac 能做到） |

- 解决“隐身后远程端无法打开设置”的问题：
  - Windows 增加托盘图标，菜单含「在录屏里隐身 ✓」「显示小窗」「开始/停止录制」「素材目录」。托盘属于任务栏，远程端能看到。
  - Mac 在应用菜单（菜单栏）中加同名勾选项。
  - 两个平台都同步在设置里提供开关。
- 只能在空闲时切换（录制、保存、恢复期间禁用）；切换后立即作用于所有已打开的窗口。`report.json` 增加 `stealthInCapture` 字段，方便剪辑时知道画面里是否有小窗。
- 关闭隐身后，Windows 仍然保留 15 秒自动收起成红圈，让录制画面里只剩边缘的一个小圆点。“排除失败时禁止录制”的检查只在开启隐身时生效。
- 已知限制写入说明：macOS 15 起，部分基于 ScreenCaptureKit 的软件可能仍能捕获 `.none` 窗口；Windows 自带远程桌面（mstsc）下的表现需要实测记录，不做保证。

### 2.2 Windows 界面对齐 Mac

- **DPI**：所有窗体设置 `AutoScaleDimensions = 96×96` 和 `AutoScaleMode.Dpi`；绝对定位改为 `TableLayoutPanel` 加锚定；自定义尺寸统一用 `LogicalToDeviceUnits`；处理 `DpiChanged` 并重新执行 `FitContent`。
- **主窗**按 Mac 的结构重排，逻辑宽度 336，内边距 16，圆角 12：
  1. 标题栏：图标、名称，右侧只保留关闭按钮（与 0.4.1 Mac 一致）
  2. 状态行：状态点、阶段，右侧显示“本地保存”
  3. 说明，最多 2 行
  4. 录制中显示计时和“15 秒无操作后收起”
  5. **机位分段选择**：摄像头 / 桌面 / 摄像头+桌面
  6. 预览折叠，带“实时画面”标签，双路时左右两格
  7. 底部一行：宽主按钮，加文件夹和齿轮两个图标按钮（Segoe Fluent / MDL2 图标字体，带 AccessibleName 和 ToolTip）

  “更改保存位置”“刷新设备”“恢复”移到设置的“高级设置”中。
- **设置窗**：沿用 Mac 结构。
  - 来源卡片：摄像头卡片含摄像头、话筒、预览和音量表；桌面卡片含屏幕缩略图、系统声音开关和播放设备。
  - 桌面分辨率、画质
  - 页脚：保存位置、“高级设置 ›”、完成
  - 高级设置：保存位置、在录屏里隐身、重新检测设备、异常素材恢复

  使用暗色标题栏（DWMWA 20），对设置窗套用统一控件样式；屏幕卡片改为自绘，缩略图和文字分区；名称显示为“显示器 1（主）· 3072×1920”，通过 `QueryDisplayConfig` 读取显示器友好名。
- **文案**与 Mac 统一：开始录制 / 停止并保存 / 录制已保存 / 素材需要检查。

### 2.3 Windows 摄像头与话筒

状态（Issue #51 / PR D）：已接入三机位、稳定设备选择、WASAPI 话筒、独立摄像头编码与双路看门狗、预览/设置、报告、合成摄像头 smoke 和 `--device-check`。当前环境无 dotnet，尚未编译或运行 Windows 检查；真实 MJPEG/YUY2、隐私拒绝、占用/拔线、长录同步、DPI 与 FCP 验收待 Windows 实机完成。未提交或发布。

- **工具链**：`build-windows-tools.sh` 增加：
  - `--enable-indev=dshow`
  - 解码器 `mjpeg,rawvideo`（YUY2/NV12 走 rawvideo）
  - 必要的 `hflip` 等滤镜，仅在需要时启用

  重新生成固定哈希（`recording-tools.sha256`）、源码包和许可说明。打包自检增加 `-f dshow -list_devices true`，确认可运行。
- **设备发现**：解析 `ffmpeg -list_devices true -f dshow -i dummy`，强制按 UTF-8 解码，保存 `@device_pnp_…` 备用名作为稳定 ID。用 `-list_options true` 选格式，优先 1080p30，其次 720p30，取设备原生帧率，MJPEG 优先于未压缩格式。
- **话筒**：复用 `Loopback` 的 WASAPI/QPC 时间戳管线，改用 capture endpoint（`eCapture`、不加 loopback 标志），写 RF64。默认使用系统默认通信或录音设备，也允许指定。
- **录制**：摄像头用独立的 FFmpeg 进程（与桌面进程隔离，任一路失败停止整个 Take 并保留所有原始素材），H.264 8 Mbps（与 Mac 一致）、CFR 30。停止后与话筒音轨合成 `camera.mp4`，文件命名和报告结构与 Mac 对齐（`mode = camera|desktop|both`、各轨起始时间）。双路时检查 `ResourceBudget` 加上两路 x264 线程的预算。
- **权限与占用**：
  - 读取 `CapabilityAccessManager\ConsentStore\webcam|microphone`。如果“允许桌面应用访问”被拒绝，提示并提供按钮打开 `ms-settings:privacy-webcam` 或 `privacy-microphone`。
  - 摄像头被 Zoom、Teams 等占用导致打开失败时，明确提示“被其他应用占用”，不自动换设备。
  - 录制中拔掉设备，按现有流程停止并保留素材。
- **预览**：每路一个 10 fps MJPEG 预览支路，沿用现有的 `select@preview` 按需开关；空闲预览只在设置页和主窗展开时打开摄像头，收起即释放（避免摄像头指示灯常亮）。

### 2.4 编码收尾

- 所有子进程的 `StandardOutputEncoding / StandardErrorEncoding` 设为 UTF-8。
- 发行包的说明文件改为带 BOM 的 UTF-8 `README.txt`；打包时检查条目名全部为 ASCII。

## 4. 验收环境

- 用户提供的 Windows 实机（BILL-SUPERMAN，SSH 经本机 2222 端口映射，已安装最新版）：smoke test、截图、DPI 矩阵、真实摄像头和远程协助对比。不会修改该机器的代理、网络、驱动或隐私设置；需要改隐私开关的测试项由用户确认后手动操作。
- Mac：`swift run --package-path clients/macos ZSirCapture --check-recording-ui` 和 `CaptureChecks`，实机检查远程软件的可见性。
- 合成检查不能替代实机结论，未覆盖的组合在验收记录里明确写出。
