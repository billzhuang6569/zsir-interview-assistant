## Encoded timeline checker

`script/check-recording-timeline.py RECORDING` invokes ffprobe to decode video frame metadata and inspect every video stream. Exit 0 means the measured checks pass; exit 1 means validation or probing failed. JSON contains counts, dimensions, actual start/end bounds, errors and measurement limits. `--require-audio` requires at least one measurable audio track; compare the Take report to verify all selected tracks are present.

The checker compares presentation timestamps with rational `firstPTS + n/30` using half a time-base tick for nearest-tick quantization, checks strictly increasing presentation order, per-frame duration when available (one tick tolerance), reported frame counts when available, and the end of the final frame against `firstPTS + count/30`. A first-frame offset is reported separately in `first_frame_offset_seconds`; CFR by itself permits it. `--require-zero-start` additionally checks the product contract origin. Current application startup/first-frame barriers are not established by these offline tests. If final frame duration is absent, stream start plus stream duration supplies the endpoint; if both are absent, validation fails. Container duration alone is never used. It accepts 1/30 stream ticks and alternation of 33/34 ticks in a 1/1000 time base. It does not require `avg_frame_rate` or `r_frame_rate` metadata to equal 30 exactly.

Audio checks compare measurable stream start/end boundaries against each video stream with a configurable default tolerance of 0.1 seconds (`--av-tolerance`). This is a boundary check, not proof of audible lip sync, internal audio continuity or drift. Codec priming/padding and different track start/end policies need interpretation on actual recordings. No audio is required by default for silent Takes.

PTS cannot reveal duplicated pixel content: both static desktop repeats and genuinely new frames have fresh presentation timestamps. Verify repeatedFrames/capturedFrames diagnostics and moving content separately. ffprobe diagnostics cause failure, but the checker is not a full independent corruption scan or platform acceptance test. Long recordings load frame JSON into memory; use offline validation with adequate memory.
