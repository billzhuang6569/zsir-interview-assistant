## 本轮补齐的实现及验证方向

macOS：精确相对帧号、NV12 采集、要求硬件编码的策略；分路有界 writer 所有权；独立启动/停止截止；后台清理真实完成之前持有素材锁；超时标记可被恢复扫描识别。合成检查覆盖一路阻塞时另一路继续编码、队列上限和失败状态。强制硬件编码且合成编码成功，不等于读取了 AVAssetWriter 内部 VideoToolbox 会话属性。

Windows：实际短片探测 Desktop Duplication 与 Media Foundation；不满足条件时记录 GDI/软件编码回退；同一录制源的预览分支在缩放与 JPEG 编码前关闭；配套 FFmpeg 的受限 select 命令补丁及完整源码；恢复副本、有限收尾与真实清理完成前的素材锁；流式长录分析。真实组件门控及设备行为仍需 Windows 验证。

## macOS 外部 CPU/RSS 采样器：仅工具验证

`script/sample-macos-process.py` 无第三方依赖，按指定 PID、时长、间隔和场景标签输出新 JSONL，拒绝覆盖已有文件。每次读取当前进程树，逐条 flush，不积累采样历史；根进程退出、PID 身份变化、无目标及采样器中断均写明结束原因。采样间隔内结束或重挂父进程的子进程可能漏记；场景标签由调用方提供，脚本不判定是否正在录制。

```sh
python3 script/sample-macos-process.py --pid 36051 --duration 5 --interval 1 \
  --output dist/validation-20261029/macos-idle-sampler-5s-final.jsonl \
  --scenario idle-sampler-validation-no-recording
```

CPU 使用 macOS `ps %cpu`：此前最多一分钟的衰减平均，不是该采样间隔的 CPU 占用；进程树求和可能超过 100%。RSS 单位 KiB，求和可能重复计算共享页，不能当作私有内存。不测量或推断 GPU、private memory、system commit。

已核对 PID 36051 的可执行路径为最终 `dist/0.4.0-test/ZSirCapture-0.4.0-macos-arm64/ZSirCapture.app/Contents/MacOS/ZSirCapture`。最终工具验证输出为上述 JSONL：5 个样本、实际 5.009 秒、正常 `duration_complete`；各样本仅根进程，`ps` CPU 合计 0.6–2.8%，RSS 合计均为 115616 KiB。这只是 idle 标签下的采样器功能验证，不是录制性能、资源下降或同机基线验收。未启动录制、请求隐私权限或改动应用包。

临时合成进程检查通过：发现子进程、根进程退出（含 zombie 状态）、初始 PID 不存在、拒绝覆盖，以及采样器 SIGTERM 后写入 `interrupted` 结束记录。只向合成采样器测试进程发送信号，未向录制应用发送信号。

### Windows 性能采样准备

`script/windows-performance-sample.ps1` 接受 TargetProcessId、DurationSeconds、IntervalSeconds、OutputJsonl、Scenario，按实际采样间隔计算应用及 FFmpeg 后代的 CPU 时间差，记录 working set/private bytes。系统 commit、GPU、磁盘与编码队列指标明确未采集。JSONL 逐行写入并拒绝覆盖。当前主机没有 PowerShell，仅人工静态检查；尚未在 Windows 解析或执行。
