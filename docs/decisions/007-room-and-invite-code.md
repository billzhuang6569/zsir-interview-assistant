# ADR-007 · 房间 + 邀请码：固定下载地址，码在引导最后一步输入

**日期** 2026-10-21 · **状态** 已采纳

## 背景
初版设计里「新建会话」会生成一条**带码的下载链接**（`/download/<code>`），安装后通过 URL scheme / 安装包文件名把码自动填进客户端。Billy 提出两点：一是「会话」和「邀请链接」两个概念叠在一起不直观；二是希望的流程是「管理端建房间、填信息、拿到一个码；嘉宾走完引导最后输码，进房间看到欢迎信息」。

## 决策
1. 术语统一为**房间**（Room）和**邀请码**（Code）；不再有「邀请链接」这个概念。
2. 客户端下载地址**固定**（`/download`），与房间无关；安装包不含任何房间信息。
3. 邀请码在客户端引导的**最后一步**输入（欢迎 → 权限 → 设备 → 自检 → 邀请码 → 欢迎卡）。前四步离线可完成。
4. 房间创建时填：房间名、导演、嘉宾姓名（可多位、可不填）、欢迎语、默认录制范围。嘉宾输码成功后看到这些信息组成的欢迎卡。
5. 控制端提供「复制邀请文案」：下载地址 + 邀请码 + 三步说明，一段话发给嘉宾。

## 放弃的方案
- 带码下载链接 + 自动填码：macOS 要注册 URL scheme、Windows 要靠安装包改名传参，两条链路都可能在嘉宾电脑上失效，而收益只是省掉手输 6 个数字。
- 码放在引导前段：码之后还有设备/自检两个可能失败的步骤，嘉宾容易搞不清是「码不对」还是「电脑不行」。
