# macOS 本地录制工具（开发版）

这是采集可行性工程，不能用于不可重来的正式采访。UI 与引擎暂在同一进程，已提供异常中断后的副本恢复入口；当前产品不包含远程控制或自动卸载。正常退出会阻止中断录制；强制退出仍可能损坏素材。

## 当前使用条件

- 用户采访通常超过 1 小时，优先内置摄像头/话筒，后期主要使用 Final Cut Pro。
- Windows 实机已通过 Tailscale 连通，尚无 Windows 产品客户端；常用会议软件待确认。
- 编译最低目标 macOS 14；当前仅在 macOS 26.6.2 / Apple Silicon / Swift 6.3 命令行工具环境构建，不代表已支持所有 macOS 14+ 设备。
- 默认使用系统摄像头、话筒、主显示器，也可在设置中指定设备。报告记录实际设备名称；这不保证默认设备一定是内置设备。

## 构建与启动

在仓库根目录运行，或点击 Codex 的 Run：

```sh
./script/build_and_run.sh
```

脚本构建 SwiftPM 工程，生成 `dist/ZSirCapture.app`，做本地 ad-hoc 签名并打开右上角小窗。它不会安装到 Applications，也不会自动录制。若应用已运行，脚本要求先停止保存、退出，避免重建杀掉录制进程。

仅构建：`./script/build_and_run.sh --build-only`。

无摄像头、无话筒、无屏幕采集的合成素材自检：

```sh
swift run --package-path clients/macos CaptureChecks
```

当前机器没有 XCTest；检查程序直接使用失败即退出的断言，验证独立目录不覆盖文件、报告写入、无样本不假成功、采集时钟转换，以及 12 秒合成视频和静音 AAC 的 MP4 封装、静止画面尾帧延长、音视频轨道、时长与完整音视频解码。另有 4K 编码及逐帧解码尺寸检查，新增单路/双路合成素材检查及连续预览样本独立性检查；七组自动检查已通过，含独立进程强杀、恢复与原文件保留检查，不请求设备权限。仅生成临时测试文件，结束后清理。不等同于设备录制或 Final Cut Pro 验收。

## 第一次试录

首次启动先完成权限引导：选择录制方式 → 允许所需权限 → 进入录制小窗。引导本身不采集或生成素材；可稍后设置，下次启动继续。录制设置中的「权限设置…」可重新进入；返回应用会自动检查授权。系统要求重新打开时，用 ⌘Q 退出后重开。已完成引导仍会在开始录制前复查，权限撤回不会被本地完成标志绕过。


1. 可选齿轮按钮选择设备、更改目录；默认 `~/Movies/ZSir Recordings`。至少留出 10 GB 空间。
2. 选择「摄像头」「桌面」或「摄像头+桌面」，点击「开始录制」。仅按所选机位请求摄像头/话筒或屏幕/系统音频权限。权限变更如要求重启，退出后重新打开。
3. 用耳机播放一段普通系统声音，同时对话筒讲话。观察状态变成「正在录制」；12 秒内收不到所选机位的完整数据会自动停止并提示。
4. 录制约 30–60 秒，点击「停止并保存」。等待「录制已保存」，再打开文件夹。
5. 每条 Take 单独目录，仅含选中机位的 `camera.mp4` 和/或 `desktop.mp4`，另有 `report.json`。导入 Final Cut Pro，分别检查声音来源、首尾画面、小窗排除及同步。
6. 录制中使用系统原生视频显示层连续显示编码器已接受的画面，不再定时抽静帧；预览繁忙时丢帧以避免延迟，录制优先。可收起以停止预览帧传递，展开不影响采集。停止后保留最后画面和时间，新 Take 清空旧图。
7. 短测通过后再做开会共存及两小时连续试录，记录设备、会议软件版本、磁盘、丢帧和起止同步差。

报告的 `finalized_unverified` 只代表写入器完成封装；`needs_review` 代表采集或保存出错。遇到失败不删除现有文件。不要把它们当成可交付素材的自动认证。

## 实现边界

- AVFoundation：摄像头＋话筒；ScreenCaptureKit：桌面＋完整系统播放声音，无会议声音过滤，无主动话筒混入。
- 摄像头优先 1080p；不支持时使用设备高质量预设，报告实际尺寸。桌面按 ScreenCaptureKit 内容点尺寸乘像素倍率采集，保留 Retina 像素，仅对齐偶数尺寸，目标 30 fps。两个文件均 H.264 / AAC；摄像头为 8 Mbps，桌面按像素数同比增加目标码率（最低 12 Mbps，4K 为 48 Mbps）。4K 桌面加摄像头每小时粗略预算约 25 GB，实际码率、负载与清晰度需实测。报告记录实际尺寸及目标码率；不支持高分辨率编码时明确报错，不静默降为 1080p。
- 相机样本从会话同步时钟映射到 host clock；两路以同一 epoch 写入。设备时钟漂移及长时间音画同步尚需实测。
- 首片目标 1 秒、后续目标 10 秒的 MP4 fragment，正常停止完成封装；实际落盘受编码器/关键帧影响。设置面板可恢复已落盘片段，不保证强杀后完整恢复。
- 本工具窗口通过屏幕流的应用过滤排除；不承诺其他会议软件的共享画面也能排除它。
- 实时写入来不及时计数并丢弃该样本，不积累无限队列；丢音频也会记录在报告中。摄像头连续 8 秒无新帧、屏幕流报错、写入错误或剩余空间不足 2 GB 时停止保存。
- 暂无音量表、倒计时和独立录制进程；恢复需要用户主动点击；这是 P0 采集工程，不能替代已设计的完整嘉宾端。
- 当前完全本地运行，移除中转、导演网页和结束任务自动卸载的开发范围。没有录后宫格。可在未录制时用 ⌘Q 退出，本地产物可手动移除，素材保留。
- ad-hoc 签名只适合本机开发，重新构建后系统可能要求重新授权。可分发签名、公证和安装包留到发行阶段。

官方依据：[AVAssetWriter fragments](https://developer.apple.com/documentation/avfoundation/avassetwriter/moviefragmentinterval)、[ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit)、本机 SDK 的 `AVCaptureSession.synchronizationClock` 注释。

### 设备选择与中断恢复

点击小窗齿轮，在开始录制前选择摄像头、话筒和显示器；默认跟随系统当前设备。连接新设备后点击“刷新设备”。系统声音仍完整采集，不能在此排除会议声音。

异常退出后重新打开，齿轮 → 异常中断恢复 → 恢复副本。恢复结果放在对应 Take 内的独立 Recovered-UUID 目录；原 MP4 始终保留。最后尚未封装的片段可能丢失，没有可读片段时无法恢复。请检查恢复时长、声音和画面，再导入 Final Cut Pro。

录制期间应用防止闲置睡眠，但合盖、强制睡眠、拔盘和断电仍可能中断；真实长录制尚待验收。


## 界面与图标（2026-10-21）

应用名称统一为“庄Sir采访录制助手”，构建脚本将 Assets/AppIcon.icns 写入 app bundle。图标沿用 Windows 已确认的 REC 与手写 Zsir 版本，程序显式加载以避免旧图标缓存。

小窗采用原生毛玻璃与暗色遮罩；由 SwiftUI 实际内容高度调整窗口，移除原来 300/180 点固定高度。单路预览放大，双路并排，折叠继续保持可见的状态和开始/停止按钮；设置继承暗色。打开尚未创建的默认素材目录会先创建，打开失败弹出提示；异常中断后即使封装成功仍显示“素材需要检查”。

本轮验证见 docs/testing/macos-ui-2026-10-21.json：构建、签名、图标封装、三种模式切换、预览折叠/展开和设置开关通过。未以此次界面测试替代长录制或 FCP 导入验收。


## 录制计时与屏幕边缘提示

录制时显示 HH:MM:SS 时长（不是逐帧 SMPTE 时间码），使用采集引擎的单调时钟；停止后保留本次计时。正常音视频已开始写入后，小窗连续 15 秒没有鼠标移动、点击、滚动或键盘操作，会隐藏到所在屏幕右边缘，留下 19 点红圈、32×40 点点击区域。红圈轻微上下跳动；系统开启“减少动态效果”时静止。

点击红圈或点击 Dock 中的应用可展开，并重新计算 15 秒。停止、保存、等待录制数据、错误或模态提示时恢复完整窗口。系统录屏过滤器继续按本进程排除所有应用窗口（包括红圈）。收起只影响窗口显示，不停止采集。

运行 `swift run --package-path clients/macos ZSirCapture --check-recording-ui` 检查跨小时计时、正常录制前不隐藏、15 秒等待、操作重置、重新展开等待期，以及错误和停止时恢复窗口。该检查模拟录制状态，不打开采集设备。此环境仅有 Command Line Tools，缺少 XCTest，沿用可执行自检模式。

## 按架构打包

```bash
BUILD_ARCH=arm64 ./script/package-macos.sh
BUILD_ARCH=x86_64 ./script/package-macos.sh
```

从仓库根目录运行，输出到 `dist/release/`，目标目录已存在时拒绝覆盖。Intel 包可在 Apple Silicon 上交叉编译；Rosetta 自检不能替代 Intel 物理机器的设备采集验收。发布包使用临时本机签名，尚未公证。

## 权限流程自检

`swift run --package-path clients/macos ZSirCapture --check-permissions` 使用隔离 UserDefaults 与模拟权限回调，验证机位映射、拒绝/受限、串行请求、迟到回调、跳过续接、完成后撤权、方式持久化及开始前阻止采集。不重置系统隐私权限、不访问设备；不替代真实 TCC 验收。主界面已将「双路」改为「摄像头+桌面」，移除初始隐私文案及空白行，保留动态录制提示。
